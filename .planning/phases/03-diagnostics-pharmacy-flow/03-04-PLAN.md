The pharmacy dispense vertical: pharmacist sees pending prescriptions live with current stock and low-stock warnings, and dispenses each atomically through the deployed dispense_medicine RPC. Delivers PHARM-01 (live pending list + stock) and PHARM-02 (atomic dispense, insufficient-stock error toast).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → dispense_medicine RPC | Stock decrement + status flip cross into a single SECURITY-DEFINER server transaction |
| concurrent pharmacists → shared stock | Two dispenses of the same medicine race on stock_qty |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Tampering / Race | stock decrement | mitigate | Only the deployed dispense_medicine RPC mutates stock (row-lock + double-dispense guard); the client performs NO stock/status write — verified by acceptance grep asserting no client-side `update({stock_qty})` |
| T-03-11 | DoS / Integrity | insufficient stock | mitigate | RPC raises "Insufficient stock" and rolls back atomically (no partial dispense); client shows the exact message as a destructive toast; button disable is UX-only, server is authoritative |
| T-03-12 | Elevation of Privilege | RPC authorization | accept | dispense_medicine runs under the caller's pharmacist grant (deployed); browser uses the anon RLS-scoped client only, no service role |
</threat_model>
