## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| doctor browser → orders/prescriptions insert+delete | clinical writes scoped by RLS to doctor role |
| medicine search input → filter | user text used ONLY for client-side array filtering |
| quantity input → prescriptions.quantity | numeric input feeding Phase-3 dispense math |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-18 | Elevation of privilege | orders/prescriptions insert + delete | mitigate | RLS-scoped anon client; the delete targets only ids from this-visit rows the client fetched under RLS; on an RLS denial STOP and surface a checkpoint |
| T-02-19 | Tampering | prescription quantity | mitigate | zod `z.coerce.number().int().positive()` blocks 0/negative/fractional quantities before insert, protecting Phase-3 stock decrement |
| T-02-20 | Injection | medicine search input | accept | Filter is a client-side `Array.filter` over an already-fetched list — input never reaches a PostgREST filter string |
| T-02-21 | Tampering | remove-order/prescription of foreign rows | mitigate | UI only exposes ids fetched by `visit_id = visitId`; RLS is the enforcement layer for any hand-crafted delete |
</threat_model>
