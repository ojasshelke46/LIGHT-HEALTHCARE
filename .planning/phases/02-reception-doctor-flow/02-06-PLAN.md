| T-02-16 | IDOR / Information disclosure | appointmentId param | mitigate | appointmentId is used only in an `.eq("id", …)` filter through RLS-scoped reads; a doctor cannot load another doctor's appointment because RLS restricts the row set (verify: opening a foreign appointmentId yields not-found) |
| T-02-17 | Tampering | optimistic status/visit state | mitigate | Optimistic values are local; failed writes roll back and re-derive from server; visit reuse (maybeSingle by appointment_id) prevents duplicate visit rows on refresh (D-18) |
</threat_model>
