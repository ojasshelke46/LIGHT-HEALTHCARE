## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| doctor browser → cross-patient history reads | clinical PII across many visits rendered to the doctor |
| patient id URL param → data load | untrusted route param used in equality filters |
| result_url from DB → anchor href | stored URL opened in a new tab |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-22 | Information disclosure | all-patients list | mitigate | List is derived from `visits.eq(doctor_id, staff.id)` with staff.id from server-verified getStaff(); RLS additionally scopes reads — a doctor cannot enumerate patients they never saw |
| T-02-23 | IDOR | patient [id] param | mitigate | Reads go through RLS-scoped equality filters; a foreign/random id yields not-found rather than data; search input never reaches a PostgREST filter (client-side only) |
| T-02-24 | Tampering | result_url anchor | mitigate | Rendered with `target="_blank" rel="noopener noreferrer"`; URL originates from staff-written rows (Phase 3 upload), not from unauthenticated input |
</threat_model>
