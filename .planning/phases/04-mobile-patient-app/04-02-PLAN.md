<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| patient client -> book_appointment RPC | Slot-id crosses into an atomic server transaction |
| patient client -> appointments/doctor_slots reads | RLS-scoped reads of own appointments; public reads of departments/doctors/slots |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | T (Tampering) | BookingWizard confirm -> book_appointment | mitigate | Booking is server-authoritative: the atomic `book_appointment` RPC row-locks the slot and rejects an already-booked slot; the client never sets `is_booked` or inserts appointments. On the 'already booked' error the UI toasts + refetches free slots. |
| T-04-06 | I (Info disclosure) | index.tsx next-appointment select | mitigate | Appointments read is RLS-scoped to `current_patient_id()`; the query carries no service role and (defensively) filters `patient_id = own id`, so no cross-patient appointment can render. |
| T-04-07 | D (Misuse/DoS) | repeated booking attempts | accept | Low-value target; the seeded slot pool is finite and each booking is guarded by the atomic RPC + Supabase rate limits. |
</threat_model>
